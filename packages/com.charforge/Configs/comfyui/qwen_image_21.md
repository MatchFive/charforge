# 路线 B：Qwen-Image-2.1（原生 RGBA 透明通道）

> 结论先说：**能跑，而且它解决了本项目最脏的一环；但它现在还补不上"四向一致性"那一环。**
> 所以定位不是"替换 SD1.5"，而是**并行的第二条路线**——见文末的分工建议。

---

## 一、你这张卡该怎么下权重

`Qwen-Image-2.1` 不是一个文件，而是**三个**（外加一个可选的提示词增强器，本仓库的工作流不带它）：

| 组成 | 作用 | 文件 |
|---|---|---|
| 7B 单流 DiT | 出图的扩散主干 | `qwen_image_2.1_int8_convrot.safetensors` |
| Qwen3-VL 8B 文本编码器 | 读提示词，**也是它能看懂中文和参考图的原因** | `qwen3vl_8b_int8_convrot.safetensors` |
| 64 通道 RGBA VAE | 四通道，透明度从这里来 | `qwen_image_2.1_vae_bf16.safetensors` |

**"transformer 不到 15G"这句话最容易误导人的地方就在这**：7B 主干 BF16 是 13.25 GB，看着刚好卡进 16 GB；但**文本编码器是另一个 8B 模型**，BF16 下 16.33 GB——单它一个就爆卡。两者相加 BF16 是 30.84 GB。

按权重总量分档（数字为磁盘占用，加载后大致相当，激活值另算）：

| 组合 | DiT | 文本编码器 | VAE | 合计 | 16 GB 可用？ |
|---|---|---|---|---|---|
| 官方 BF16 | 13.25 | 16.33 | 1.26 | **30.84 GiB** | ✗ 差一倍 |
| ComfyUI INT8 + INT8 编码器 | 6.76 | 8.71 | 0.63 | 16.10 GiB | △ 贴边，易 OOM |
| GGUF Q8_0 + Q8_0 编码器 | 7.12 | 8.11 | 0.63 | 15.86 GiB | △ 贴边 |
| **INT8 DiT + W4A8 编码器** | 6.76 | 5.88 | 0.63 | **13.27 GiB** | **✓ 推荐** |
| GGUF Q4_K_M + UD-Q4_K_XL | 3.91 | 4.80 | 0.63 | 9.34 GiB | ✓ 有余量，质量有损 |

**给你的 4070 Ti SUPER 16 GB 的结论：走第四行。** 同档 16 GB 卡的实测口径是峰值约 12–14 GB，
1024×1024 / 20–25 步约 25–35 秒每帧。权重合计 ≈13.3 GB，磁盘上三个文件约 17 GB。

不建议一上来就用 BF16，也不建议为了"省心"直接掉到 Q4——**Q4 会把 8B 文本编码器的语义能力削掉**，
而那正是你要用它读"南宋""龙泉窑"的部分，得不偿失。

### 前置条件（不满足会以各种奇怪方式失败）

| 条件 | 说明 |
|---|---|
| ComfyUI **≥ 0.37.0** | 0.36 及以前**完全没有** Qwen-Image-2.1 节点，加载工作流会整片报"节点缺失" |
| PyTorch **cu130** | `int8_convrot` 的文件是给 CUDA 13 内核编的；CUDA 版本不够时 ComfyUI 会静默关掉这些内核，速度掉一截 |
| 用 GGUF 的话 | 必须换成 **leejet 版**的 `ComfyUI-GGUF`；用 city96 版会在加载时直接报错 |

模型放 `ComfyUI/models/` 下对应的子目录：`diffusion_models/`、`text_encoders/`、`vae/`。

## 二、怎么接到 CharForge

本目录已备好一对可直接用的文件：

```
charforge_qwen21_txt2img.workflow.json     # API 格式，扁平节点，能直接被插件提交
charforge_qwen21_txt2img.bindings.json     # 节点绑定
```

这份工作流是从**官方模板的 subgraph 展开**出来的。官方模板（Templates 面板里的
"Qwen-Image-2.1 Text to Image"）把整条生成链包在一个 subgraph 节点里，
**subgraph 不能被 `/prompt` 接口直接提交**——这是它和 SD1.5 工作流最大的差别，
硬提交只会得到一个含糊的报错。所以我按官方内部连线还原成了扁平节点，
并去掉了其中的提示词增强器（那是**另一个 9B 模型**，默认开关是关的，留着白占显存）。

步骤：

1. 先在 **ComfyUI 界面里手工 Queue 一次**这份工作流，确认能出图；
   这一步不能跳过——否则插件只会给你一个超时错误，看不出真正原因。
2. 确认输出是**带透明背景的 PNG**（见下一节）。
3. 插件窗口「后端设置」：地址 `http://127.0.0.1:8188`，工作流指向这个 JSON 的绝对路径。
4. 点「探测后端」应显示 `ComfyUI 就绪`，然后点「生成并装配」。

## 三、它对本项目的三个真实差异

### 1. 原生 alpha —— 抠图这一环自动让路

官方推荐的提示词写法是**首尾各加一句**，这正是工作流里已经写好的：

```
This is an RGBA image with transparency. … The image has alpha channel and the background is transparent.
```

（必须存 PNG，存 JPG 会把 alpha 丢掉。）

这一步的价值比"多一个抠图功能"大得多：**透明度属于生成模型本身，而不是事后补救**。
我们上一版加的那个 `LocalMatting` 色键兜底会因为"检测到已有 alpha"而**原样放行**，
不会去破坏它——也就是说这条路是干净的，不是绕过去的。

而且它直接治好了上一版那个碰撞体缺陷的**根因**：`FrameNormalizer` 是按 alpha 裁切并量包围盒的，
真 alpha 进来，量出来的就是角色本身；不会再有"包围盒等于整幅画布"这种事。

### 2. 中文提示词直接进模型 —— 术语表在这一路不是必需的

`qwen3vl_8b` 是多语言视觉语言编码器，**支持中文与中英混排**。
所以 `Configs/prompt_glossary.json` 那套"中译英"在这一路**不是必需品**——
它是为 SD1.5 的英文 CLIP 词表才存在的。

对文博场景这是实打实的收益：「南宋」「龙泉窑青釉」「开片」这些词，
**让它直接读原文，比先翻成英文再喂给只认英文的编码器要准**，也省掉了一层语义损耗。

（一处待改：流水线目前对 ComfyUI 后端**无条件**跑术语表，并会对残留中文发告警。
换到 Qwen 后那条告警是**误报**——中文在这一路能进模型。见文末待办。）

### 3. 生成 1024、画布 512 —— 所以绑定里**故意不绑宽高**

Qwen-Image-2.1 的建议总像素量是 **100 万到 400 万**，而项目的画布是 512×512 = **26 万**，
低于下限一个数量级。所以正确做法不是"逼它出 512"，而是：

```
Qwen 出 1024×1024  →  FrameNormalizer 按 alpha 裁切、盒式降采样到 512 画布
```

`bindings.json` 里因此**没有** `width` / `height`：节点 5 保持 1024，缩放交给流水线。
如果你把宽高绑上，就等于强制它用 512 出图，质量会明显掉。顺带一提边长要是 16 的倍数（建议 32）。

## 四、它现在还做不了的事：姿势锁定（这是关键）

四向一致性靠的是 ControlNet 锁姿势，而：

- **`Qwen-Image-2.1-Fun-ControlNet-Union` 确实存在**：一个约 7.5 GB 的控制分支，
  含 Pose（DWPose 骨架）在内共 8 种条件 + 局部重绘，以 `strict=False` 挂在冻结的主干上。
- **但它的 ComfyUI 支持还没并入稳定版**（PR #16519 仍在 review 中）。
  现在只有 Kijai 的实验性补丁，或走官方的 VideoX-Fun（Python 侧，不在 ComfyUI 里）。
- 即便并入了，**7.5 GB 控制分支 + 13.3 GB 权重 ≈ 21 GB**，16 GB 上必然大量换页，
  速度会难看到不能用于批量出 16 帧。

**结论：这一路现在解决"资产干净"，解决不了"四向一致"。**

## 六、采样参数（和 SD 系完全不是一套直觉）

| 参数 | 值 | 说明 |
|---|---|---|
| `cfg` | **1.0** | Flow Matching 标配。**不要照 SD 的习惯拉到 7**，会出现过饱和、蜡感皮肤、手指畸变 |
| `steps` | 25–40 | 官方默认 40，模板 25，25 步已可用 |
| `sampler_name` | `euler` | |
| `scheduler` | `simple` | |
| `denoise` | 1.0 | |
| `negative_prompt` | 空 | **cfg=1 时负向不生效，留空是正常的**，不是没接上 |

另外两条反直觉的：**模型是 LLM 编码的**，所以

- 提示词权重语法（`(word:1.2)`）**不生效**，会被当成普通标点；
- `masterpiece, best quality` 这类质量咒语**毫无作用**，写句子比堆标签有效。

## 七、排查表

| 现象 | 原因 | 处理 |
|---|---|---|
| 加载工作流整片"节点缺失" | ComfyUI < 0.37.0 | 升级到最新版（稳定版没有就上 nightly） |
| 出图很慢，显卡跑不满 | PyTorch 不是 cu130，int8 内核被关 | 换 cu130 版 PyTorch |
| 2048 出图 OOM | 边长翻倍是**16 倍**注意力开销 | 用 1024 出图，看中的帧再回炉放大 |
| 出图没有透明背景 | 提示词没按官方句式写，或存成了 JPG | 首尾两句照抄；输出格式必须 PNG |
| 出图与角色描述无关 | 提示词没写进节点 | 已修（`v0.3.1`）：绑定现在会认 `prompt`/`negative_prompt`，并会明确告警 |
| 颜色发灰/发花 | VAE 用错了 | 必须用 `qwen_image_2.1_vae_bf16`，旧版 Qwen-Image 的 VAE 不通用 |

## 八、两条路线怎么分工（建议）

| | 路线 A：SD1.5 + ControlNet | 路线 B：Qwen-Image-2.1 |
|---|---|---|
| 定位 | **一致性主力**：16 帧、四向、靠骨架图锁姿势 | **资产与合规主力**：单帧母版、干净 alpha、中文考据 |
| 四向一致性 | ✓（已可用） | ✗（ControlNet 未并入稳定版） |
| 透明通道 | 需本地抠图兜底 | ✓ 原生 |
| 中文提示词 | ✗ 必须译英 | ✓ 直接可用 |
| 许可 | 宽松 | 非商用，需授权 |
| 速度（16 帧） | 约 1 分钟 | 约 7–10 分钟 |

**可执行的下一步（按顺序）：**

1. 装好 ComfyUI ≥0.37.0 + cu130，下齐 INT8 DiT / W4A8 编码器 / RGBA VAE 三个文件；
2. 用 `charforge_qwen21_txt2img.workflow.json` 在 ComfyUI 里**手工跑通一次**，
   提示词填「南宋 龙泉窑 青釉」这类中文，确认出图是**透明 PNG**；
3. 接进插件跑一次，看 `Assets/CharForge/<jobId>/sheet.png`：
   这一轮的验收点是**透明通道与角色轮廓贴合**，不是四向；
4. 四向一致性仍走路线 A（SD1.5 + ControlNet + `CharForge/pose_templates/` 骨架图）；
5. 等 Fun-ControlNet-Union 并入 ComfyUI 稳定版后，再回来把两件事合并——
   那时"干净 alpha + 中文考据 + 姿势锁定"才第一次同时成立。
